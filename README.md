# 同声传译 · Live Interpreter

[![Self-test](https://github.com/small-student-shi/live-interpreter/actions/workflows/ci.yml/badge.svg)](https://github.com/small-student-shi/live-interpreter/actions/workflows/ci.yml)

**This tool is intended solely for personal learning and assistance. Translation results come from third-party public APIs; please comply with the relevant terms of service.**
**本工具仅用于个人学习与辅助，翻译结果来自第三方公开接口，请遵守相应服务条款。**

本地运行的双语同声传译字幕工具。**界面简洁（Apple 取向），功能不缩水**：边说边出原文 + 译文，
带上下文精修、术语表、浮窗置顶字幕、全屏沉浸字幕、SRT/文稿导出。

- **英译中优先**：主力通道是腾讯翻译（~100ms），英文长句、口语都稳；术语表 + 上下文重译保准确
- **国内直连优先**：腾讯 / 有道 无需 VPN 即可用；境外通道只在可用时才参与择优，国内通道永不经过代理
- **双击即用，端口自动避让**：8787 被占用会自动换到 8788、8789……并按真实地址打开浏览器
- **全程免费**：语音识别用浏览器本机引擎，翻译走免费公开通道，不需要任何 API Key，不产生费用

## 一、怎么运行

1. 确认装过 [Node.js](https://nodejs.org)（18 以上，LTS 即可）。
2. **双击项目目录里的 `启动同声传译.cmd`** —— 它会起本地服务并自动打开浏览器。
3. 页面打开后点底部**圆形话筒按钮**（或按 `Ctrl / ⌘ + K`），首次会请求麦克风权限，允许即可。
4. 对着麦克风说话：上方是**原文**，下方大字是**译文**，逐句累积。

> 浏览器请用 **Chrome 或 Edge**（语音识别依赖其内置引擎）。Firefox / Safari 不支持语音识别，会给出提示。

## 二、便携运行：拷到任何电脑都能用

**整个文件夹拷到任意路径即可运行**（U 盘、网盘、桌面、含空格或中文的目录都行），
目标是全新电脑时也不需要装 Node、不需要管理员权限、不需要联网安装：

```
LiveInterpreter/            ← 整个文件夹拷走
  启动同声传译.cmd            ← 双击这个
  runtime/node.exe          ← 内置 Node 运行时（约 80MB，自带就不求人）
  setup-node.ps1            ← 仅在没带运行时时才会被用到
  server.mjs  proxy-boot.mjs  public/  README.md
```

启动器按这个顺序找 Node：**内置运行时 → 系统已装的 Node → 让 `setup-node.ps1` 自动下载**
（自动下载走国内镜像：阿里云 / npmmirror / 清华，最后才试 nodejs.org）。

### 生成便携包

```bash
node makeportable.mjs                        # 默认输出到 桌面\LiveInterpreter
node makeportable.mjs --out D:\LiveInterpreter
```

打包脚本会校验两处**极易踩坑的编码问题**并在输出里报告：

- `启动同声传译.cmd` 必须是**纯 ASCII 无 BOM**。中文 Windows 的 cmd 用 GBK 解析批处理，
  文件里混入 UTF-8 中文会被切碎成 `'em' is not recognized` 之类的报错，控制流随之错乱。
- `setup-node.ps1` 必须是**纯 ASCII**。Windows PowerShell 5.1 不用 BOM 时按 ANSI 读 `.ps1`，
  含中文会直接解析失败。

中文提示都由 Node 打印（Node 输出 UTF-8，不会乱码），所以脚本本身可以保持纯 ASCII。

### 实测过的路径

| 场景 | 结果 |
| --- | --- |
| `…\Temp\li-plain\` | ✓ 启动、翻译、用内置运行时 |
| `…\Temp\li with space\`（含空格） | ✓ 同上 |
| `…\Temp\li 中文 目录\`（含中文） | ✓ 同上 |
| 目标机没装 Node → 自动下载 | ✓ 阿里云镜像 105 秒下载 28MB，只保留 node.exe |
| Node 20 / Node 22 / Node 24 | ✓ 都兼容 |

> 程序**零外部依赖**：所有脚本只用 `node:` 内建模块，没有 `package.json`、没有 `node_modules`，
> 所以不存在 `npm install` 这一步，拷贝即用。

想手动验证便携性：

```bash
node portabletest.mjs                        # 自动拷到空格/中文路径下用启动器实测
node portabletest.mjs --runtime D:\node\node.exe
```

**别想在命令行里跑了**，这种事情只有作者能干

### 端口会自动避让

**不需要手动换端口。** 默认从 `8787` 开始，若被别的程序占用，会自动改用 8788、8789……
直到找到空闲端口，并按**真实地址**打开浏览器（终端里也会打印实际地址）。想指定起始端口：

```powershell
node proxy-boot.mjs --port 9000 --open
```

### 关于「文字跳动」

说话期间实时翻译每 0.4 秒左右刷新一次。为避免文字看起来一直在跳，渲染做了两层处理：
**内容签名去重**（只有内容真变了才改 DOM）＋ **两条渲染路径**（原文即时、其余合帧）。
详见下面「GPU 占用」一节。

## 四、GPU 占用：实测数据与三档切换

界面要好看难免吃 GPU，所以这里不给感觉、只给数字。
设置 → 性能 → **「实测各效果开销」** 会在你本机跑一遍并列出结果。以下是参考机
（Intel UHD 核显 + Chrome）实测的 p95 帧时间，vsync 基线 16.7ms：

| 配置 | p95 帧时间 | 结论 |
| --- | --- | --- |
| 全部开启（毛玻璃 28px） | 21 ~ 29ms | 基准 |
| **关掉毛玻璃** | **12.6ms** | **省 40% ~ 80%，唯一的大头** |
| 毛玻璃半径 28px → 10px | 21ms | 只省 0~3%，**半径几乎不影响成本** |
| 关阴影 / 关背景光斑 / 关动画 | 21ms | 各 0~1%，基本免费 |

**关键发现**：`backdrop-filter`（卡片毛玻璃）是**像素级固定开销** —— 减小半径没有意义，
只能「开或关」。所以档位就围绕它设计：

| 档位 | 毛玻璃 | 其余效果 | 适用 |
| --- | --- | --- | --- |
| 完整效果 | 开（28px） | 背景光斑 + 动画 + 完整阴影 | 独显 / 想最好看 |
| **均衡（默认）** | **关** | 其余全部保留 | 观感几乎无差别（卡片本就是不透明毛玻璃色），核显推荐 |
| 省电 | 关 | 光斑 / 动画 / 阴影再关，音量条停跑 | 老机器、笔记本省电 |

### 另外三处与 GPU 有关的真实修复

1. **渲染分两条路径**：说话时识别事件每秒可能来十几个，原来每个事件都重绘整块
   （含毛玻璃卡片，内容一变就要重新合成）。
   - 原文行 → **快路径**：同步写入，保证「说的字马上出现」；
   - 译文区 / 上几句 / 语言标记 / 浮窗 → **合帧**：每帧最多提交一次。

   实测：60 次连续事件，译文区只重绘 **1 次**（原来 60 次），原文仍零延迟可见。

2. **翻译请求节流**：原来连续临时结果会**每个事件都发一次翻译请求**
   （30 个事件 = 30 次请求，费流量也费通道额度）。现在合并为只发最后一次 ——
   实测 30 个事件 → **1 次请求**。

3. **音量条降到 30fps**，且只在数值真的变化时才改 DOM（省电档完全不跑）。

> 说明：任务管理器里的 GPU 占用包含 `dwm.exe`（桌面合成）、浏览器合成器与系统进程，
> 不等于本程序的占用。想看本程序真实开销，用设置里的「实测各效果开销」，
> 或把档位在「完整 / 省电」之间切换对比。

## 五、翻译通道：国内直连优先，英译中优先

**默认不需要 VPN。** 通道按「国内直连 → 境外」排序，境外通道只在可用时才参与择优：

| 优先级 | 通道 | 直连？ | 实测 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | **腾讯翻译**（TranSmart） | ✅ 国内直连 | **~100ms** | 无需 Key；中英双向质量高、长句稳、无频率限制。**英译中首选** |
| 2 | **有道翻译** | ✅ 国内直连 | ~150ms | 无需 Key；译文自然、口语化好。免费端点会限流（411/102），已加请求节流 + 退避重试 + 语言校验 |
| 3 | MyMemory | 视网络 | ~1700ms | 公共 API，有每日额度，兜底用 |
| 4 | Google 翻译 | ❌ 需代理 | ~250ms（有代理时） | 质量好，但大陆直连时通时断 |
| 5 | Bing 翻译 | ❌ 需代理 | ~1300ms | 已改用 LLM，中文好；但受风控会返回空 |
| 6 | Edge 翻译 | — | 已失效 | 微软 2025 年封停（404），保留在链尾熔断探活，恢复即可用 |

**启动时会自动探测每条通道**（真实请求一次），按「实测可用性 + 延迟」重排；某条挂了会被熔断跳过，
并自动切到能用的通道。界面「设置 → 检测翻译通道」可随时看到每条通道的实测结果与当前顺序。

国内通道**永不经过代理**（`NO_PROXY` 白名单），既不浪费你的代理流量，也不会绕远路变慢。

### 英译中实测对照

| 原文 | 腾讯翻译 | 有道翻译 |
| --- | --- | --- |
| It is lighter, faster, and more affordable than ever before. | 它比以往任何时候都更轻，更快，更实惠。 | 它比以往任何时候都更轻、更快、更实惠。 |
| Sorry, I did not catch that. Could you say it again? | 对不起，我没听清楚，你能再说一遍吗？ | 对不起，我没听清楚。你能再说一遍吗？ |
| We are running about ten minutes behind schedule. | 我们比预定时间晚了大约十分钟。 | 我们比预定时间晚了大约十分钟。 |

### 语种识别也走国内通道

语言探测一旦失败就可能把法语/西语当成英语、导致译文出错，所以探测顺序同样是**国内优先**：

1. 文字系统特征判断（离线、零延迟）：中文/日文/韩文/俄文/阿拉伯文等非拉丁文字直接判定
2. 腾讯 TranSmart 的 `src_lang`（~100ms，国内直连）
3. Google gtx 的语言探测（带置信度门槛，用来区分法/西/德）
4. 最后才退回文字系统结论 —— **绝不无条件默认成英语**

## 六、为什么译文比较准 / 比较自然

1. **说完再精修**：说话过程中的临时结果先做轻量翻译（快），一旦整句说完，立刻用**带上下文的重译**替换掉，
   人称、时态、指代更连贯（上下文行数可在设置里调 0–3 行）。
2. **多通道择优 + 熔断 + 节流**：见上表。手动指定通道时**严格使用该通道**，不可用就如实报错，
   绝不静默换成别的通道骗你说"成功了"。
3. **术语表保护**：设置里按 `原文=译文` 一行一条填。命中的词先替换成占位符再送翻译，译后还原，
   专有名词、产品名、人名前后绝对一致（例：`人工智能=AI`）。
4. **缓存与去重**：同样的话 30 分钟内直接命中缓存，毫秒返回；并发同请求只发一次。

## 七、关于网络代理

Node 的 `fetch` **不会**读取 Windows「Internet 选项」里的系统代理，直接跑会表现为「浏览器能打开网页、
翻译却全部超时」。所以 `proxy-boot.mjs` 会先探测系统代理，再以带代理的方式拉起服务——
**境外通道走代理、国内通道直连**，对使用者透明。

即使你完全不开代理，腾讯 + 有道这两条国内通道也能独立支撑英译中/中译英，只是少了境外通道的交叉择优。

## 八、文件结构

```
启动同声传译.cmd        双击即用：自动找 Node（内置运行时 → 系统 Node → 自动下载）→ 起服务 → 开浏览器
                        ★ 必须是纯 ASCII 无 BOM，否则 cmd 会把命令切碎
setup-node.ps1          仅在目标电脑没有 Node 时使用：从国内镜像下载便携运行时（只保留 node.exe）
                        ★ 必须是纯 ASCII，PowerShell 5.1 按 ANSI 解析 .ps1
makeportable.mjs        生成便携包（拷到任何电脑双击即用），并校验上面两个脚本的编码
runtime/node.exe        内置 Node 运行时（可选，约 80MB；带了就完全不依赖目标电脑环境）
proxy-boot.mjs          启动引导：代理接管（境外走代理 / 国内直连）+ 端口自动避让 + 打开浏览器
                        注意：本文件是「无副作用模块」，可被测试脚本安全 import
server.mjs              零依赖服务：托管界面 + 翻译转发（多通道链 / 启动探测排序 / 熔断 / 节流 / 缓存 / 语种探测）
                        端口被占用时也会自行避让，与启动引导互为兜底
selftest.mjs            服务端自检：53 项断言，覆盖通道可用性、英译中方向正确性、语种判定、熔断、缓存、HTTP 路由
porttest.mjs            端口避让测试：占住端口后启动，验证自动换端口、服务可用、原服务不受影响、无残留进程
portabletest.mjs        便携性测试：拷到「普通 / 含空格 / 含中文」路径下用启动器实测，并验证优先使用内置运行时
perftest.mjs            渲染开销审计（有界面模式）：逐项实测毛玻璃/阴影/光斑/动画的帧时间代价，
                        并验证「原文即时 + 其余合帧」与「翻译请求节流」
piptest.mjs             浮窗与输入稳定性测试：假识别引擎记账 start/stop，验证开浮窗不打断输入、
                        静默掐断能被守护救回、朗读策略、前几句同屏显示、记录持久化与重载恢复
piplive.mjs             **真·浮窗测试（有界面模式）**：headless Chrome 不支持画中画、合成 click() 也不算
                        用户手势，所以这里用有界面浏览器 + CDP 真实鼠标事件把浮窗真正打开，
                        再验证浮窗内字幕同步、显示开关、字号、主线程未冻死、开浮窗后每句仍能出译文
uitest.mjs              界面端到端测试：用 CDP 驱动真实 Chrome 跑完整链路（识别→翻译→渲染→朗读→导出）
public/
  index.html            界面结构
  style.css             设计系统（Apple 取向：系统字体、毛玻璃、连续圆角、明暗双主题）
  app.js                语音识别 · 翻译管线 · 字幕渲染 · 导出 · 浮窗 · 术语表 · 快捷键
README.md               本文件
```

自检（会真实请求免费通道，不产生费用）：

## 九、常见问题

**说话没反应？**
看浏览器地址栏左侧的麦克风权限是否允许；确认系统「隐私 → 麦克风」里允许了浏览器。Windows 还可在
`设置 → 系统 → 声音 → 输入` 里确认默认设备。多麦克风时在设置里手动指定。

**提示「识别出错：network」？**
语音识别需要联网（识别在浏览器厂商的引擎里完成，本工具的服务器不接收任何音频）。检查网络或代理。

**译文偶尔要等一两秒？**
腾讯一般 100ms 出结果。若某条通道被限流（有道免费端点偶发 411/102），会自动退避重试或切到别的通道，
顶栏状态胶囊会显示当前实际使用的通道。

**识别时不时断掉？**
浏览器（Chrome）的语音识别会以**不触发任何事件**的方式被静默掐断 —— 常见诱因是切换音频设备、
朗读译文（TTS 与识别抢同一路音频）、窗口失焦、开浮窗/全屏、长时间静音超时。
本工具做了三层防护：

1. **识别守护**：每 2.5 秒检查识别是否还活着，断了就自动救回（底栏出现橙色 ↻ 徽标，点开有记录）；
2. **窗口状态检查**：窗口重新可见 / 获得焦点时立即检查并恢复；
3. **朗读策略**：默认「聆听时不朗读」，从根上避免 TTS 抢音频；想边听边读可在设置里改成「总是朗读」。

浮窗字幕里也有一个「恢复输入」按钮和 `● 识别中 / ○ 未聆听` 状态指示，一眼就能看出识别是否还在跑。

**复制按钮提示「系统剪贴板不可用」？**
浏览器在非用户手势或权限受限时可能拒绝写剪贴板，此时会自动打开一个小窗口并把内容全选好，
按 `Ctrl + C` 即可。

**能用哪些语言？**
21 种，含中（简/繁）、英、日、韩、法、德、西、俄、意、葡、阿、印地、泰、越、印尼、马来、土、荷、波。
其中最完整、最优先优化的是**英 ↔ 中**。

**会不会花我的钱？**
不会。没有账号、没有 Key、没有付费接口，也没有遥测。唯一的外部请求就是发往免费翻译通道的文本。
国内通道直连，不占用、也不需要你的代理。

**隐私**
音频只进浏览器的识别引擎，本工具的服务器只接收**文字**（用于翻译），不落盘、不记录、不外传；
关闭服务即全部停止。所有记录只留在当前页面内存里，刷新即清空（导出才会落成文件）。
